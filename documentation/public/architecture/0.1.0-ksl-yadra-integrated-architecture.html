Yadra — Spec-to-Code Binder

Yadra lie le code à la spec KSL scellée. La spec est le document de la feature — pas une pile de .md obsolètes : elle se met à jour quand la feature évolue ; un upgrade majeur ouvre une nouvelle spec. Architecture à Deux Timelines : l’KSL est l'unique porte d'entrée vers le code cible. Le cœur Yadra instancie un Modèle IA dédié et spécifié par requête, branché au contexte projet par l’KSL et les SKILLS, et certifié par une conformité formelle étanche.

Triade · COMPRENDRE → PRODUIRE → LIVRER (CLI 0.1.8)

Le SVG ci-dessous a été aligné sur LIVRER (plus « EXÉCUTER »). En T2, la boucle qualité (Gradle + repair) vit dans B · PRODUIRE (yadra execute) ; C · LIVRER = scellement T1 ou Gate T2 (yadra gate). C · LIVRER n’est pas « 100 % sans IA » : SKILL + plan, et gate --produce (docs/e2e). Les oracles (validate, digest seal, verdict Gate) restent des fonctions CLI déterministes, découplées du LLM producteur (B / --produce).

  • A · COMPRENDRE — yadra plan ; spécialisation embarquée dans execute.
  • B · PRODUIRE — yadra execute · phase.execute · boucle sandbox/repair (budget) → PROJECT_HOME.
  • C · LIVRER — T1 : validate + seal ; T2 : yadra gate · phase.gate · bundle + verdict Conformance Gate.
  • Stack T2 — langage/build dans root.project.ksl ; yadra execute matérialise sous PROJECT_HOME (pas un repo Java/Kotlin « externe » imposé).

Scénarios de retour — circulation des données

Flux entre entités (humain, Yadra A/B/C, Conformance Gate) et technologies (KSL, SKILLS, LLM, Gradle, FluentTest, SQL, OpenTofu). Les retours ne réécrivent jamais le bundle certifié : ils remettent un payload borné dans B (T2) ou dans le contrat T1.

Données aller (contrat → artefacts) Retour C → B (build / tests) Retour VIOLATED → B Retour UNDECIDABLE → T1 / humain SATISFIED → bundle scellé

2. Les 4 Grandes Ruptures de l'Architecture Yadra

Pourquoi Yadra n’est ni un énième agent de « Vibe Coding », ni un atelier de méthodes formelles inerte : un saut de paradigme vers l’ingénierie logicielle déterministe et vérifiée.

Rupture 01 · Pivot IR

L’KSL comme « IR » (Représentation Intermédiaire) du Développement IA

De même que LLVM a standardisé les compilateurs en introduisant une IR pivot entre les syntaxes sources et le binaire machine, Yadra introduit l'KSL comme pivot sémantique entre l'expression métier humaine et le code généré.

Sur le marché actuel Saut aveugle « Prompt / Jira flou ──► Code source touffu ». Chaque itération réinterprète le code, causant hallucinations, régressions et perte immédiate de l’intention originelle.
L'innovation Yadra Le KSL fige le contrat déclaratif invariant (modules, règles, stratégies) avant d'émettre le moindre artifact. Le code n'est qu'une projection transitoire de cette vérité.
Rupture 02 · Évaluation Externe

Oracle Conformance Gate vs phase LIVRER (Fin du Juge & Partie)

La phase C · LIVRER (SKILL, gate --produce, scellement orchestré) n’est pas « sans IA ». En revanche le verdict Conformance Gate (SATISFIED | VIOLATED | UNDECIDABLE) est calculé par des oracles CLI déterministes, découplés du LLM qui produit en B ou en --produce.

Sur le marché actuel L'agent IA est juge et partie : c’est le même LLM qui produit le code, rédige ses tests de complaisance et décrète que « tout fonctionne », créant une illusion d'autonomie non auditable.
L'innovation Yadra KSL Snapshot × (Artifacts + Evidence) ⟹ Verdict. La porte de conformité rejette sans appel tout output dont les preuves d'exécution ne satisfont pas rigoureusement le KSL figé.
Rupture 03 · Déterminisme

Le Traitement de l’`UNDECIDABLE` & l’Arrêt Monotone

Le système transforme les ambiguïtés et contradictions métier en un résultat mathématique de premier ordre, bannissant tout bricolage silencieux de l'IA.

Sur le marché actuel Face à une spec floue ou un conflit fonctionnel, l'IA « devine » ce qui l'arrange ou boucle indéfiniment jusqu'à épuisement du budget de tokens, modifiant la spec à l'insu de l'équipe.
L'innovation Yadra Si une exigence est contradictoire ou non traçable, le verdict UNDECIDABLE bloque net le run, consigne la cause exacte et force l'arbitrage humain sur le contrat initial.
Rupture 04 · Deux Timelines & Ancrage

La Ségrégation en 2 Timelines & l'Ancrage Projet (KSL + SKILLS)

L'KSL est l'unique porte utilisée par Yadra pour lier le code du projet cible à la spec. Le binder sépare rigoureusement la formalisation de la spécification de la matérialisation du code.

Sur le marché actuel Mélange amorphe en une seule passe : l'agent tente de coder directement depuis des tickets ou prompts vagues, dérivant sans contrat invariant et s'appuyant sur des RAGs probabilistes non ancrés.
L'innovation Yadra Deux Timelines étanches : T1 distille l'intention métier (Doc First + KSL existant) en contrats KSL scellés. T2 compile les livrables cibles strictement et uniquement depuis le KSL. Dans les deux cas, Yadra ancre sa compréhension au contexte projet via l'KSL et les SKILLS.
