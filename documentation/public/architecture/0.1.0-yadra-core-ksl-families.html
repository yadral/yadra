Les 4 familles KSL — détail

Chaque bloc de spec alimente une couche du runtime ; les SKILLS ne dupliquent pas le vocabulaire KSL.

Famille 1

Intention & preuve métier

  • intention, scope, usecases
  • flows, references, meta
Côté Yadra : contexte pour A · COMPRENDRE (LLM T1/T2) et oracles Conformance Gate. Pas des SKILLS.
Famille 2

Contrats & cibles techniques

  • openapi, integrations, messaging
  • data, storage, communications (project)
Paramètres des ArtifactProducers : où brancher API, topic, bucket, schéma SQL.
Famille 3

Manifeste de livraison

  • outputs.kinds, blocs docs, e2e
  • outputs.kinds (manifeste unique)
Décide quels producteurs lancer et avec quelle config (routes Swagger, scénarios e2e).
Famille 4

Style & gouvernance

  • strategies, budget (niveau spec)
  • stack, repo (project root)
SKILLS déduites + moteur (budget, boucles C→B). Jamais skills { } dans le KSL.

SKILLS + fonctions — uniquement en B · PRODUIRE (rappel)
